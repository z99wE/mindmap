# Full 5/5 Production-Readiness Plan

## Strategy
Additive-first: create new files and add capabilities without changing existing logic. Where existing files must change, make minimal, focused edits with zero behavioral impact on existing flows.

## Phase 1: CI/CD & Supply Chain (new files only — zero breakage risk)

### 1.1 GitHub CI/CD Pipeline
- **`.github/workflows/ci.yml`** — Pre-merge CI running on PR/push:
  - `npm ci` → `npm run lint` → `npm run test:all` → `npm run coverage` → `npm audit --audit-level=high`
- **`.github/workflows/security.yml`** — Security scans:
  - CodeQL analysis (JavaScript/TypeScript)
  - Gitleaks secret scanning
  - `npm audit` with fail on high severity
- **`.github/workflows/release.yml`** — Post-merge release:
  - Runs full CI, generates SBOM, deploys to Render
- **`.github/dependabot.yml`** — Auto-dependency updates
  - Weekly checks for npm, GitHub Actions, Docker
  - Group non-breaking updates

### 1.2 Code Quality Tooling
- **`.eslintrc.json`** — ESLint config for Node.js (extends `eslint:recommended`)
- **`.prettierrc`** — Prettier config (matching codebase style)
- **`.editorconfig`** — Editor basics
- **`scripts/sbom.js`** — Generate CycloneDX SBOM from package.json
- **`THIRD_PARTY_NOTICES`** — Generated license file

### 1.3 Infrastructure Scanning Configs
- **`osv-scanner.toml`** — OSV-Scanner config for vulnerability scanning
- **`.trivyignore`** — Trivy ignore rules (if needed)

## Phase 2: Security Hardening (low-risk existing file changes)

### 2.1 Server Startup Validation (`server.js`)
- Strengthen production env var checks: require all 10+ critical vars before starting
- Add startup self-test: DB connectivity + LLM key availability + VAPID validity
- Add warning if running with default JWT_SECRET or ENCRYPTION_KEY

### 2.2 Rate Limiting (`server.js` + `src/routes/process.js`)
- Add per-user rate limiting on `POST /api/process` (LLM endpoint) — 30 req/min/user
- Add per-user rate limiting on `POST /api/memory` — 60 req/min/user
- Use `req.user.userId` for user-tiered limits

### 2.3 RLS Re-enablement (`src/db.js` + `src/auth.js`)
- **Critical: Do NOT break existing queries.** Add `app.user_id` setting in `authMiddleware` after JWT verification.
- Re-enable RLS on memory_graph, channels, notifications, billing_transactions, thought_revivals
- Add RLS policies that check `current_setting('app.user_id')`
- Keep the DISABLE statements as fallback with a startup health check

### 2.4 Security Hardening (`server.js`)
- Add `csurf` or double-submit cookie pattern for state-changing requests
- Add `permissions-policy` header via helmet
- Add strict transport security (HSTS) via helmet

### 2.5 Webhook Schema Validation
- Add payload schema validation for Slack, WhatsApp, SMS, Twitter webhooks using JSON Schema or Joi
- Reject malformed webhook payloads before processing

## Phase 3: Operations & Monitoring (low-risk additions)

### 3.1 Structured Logging
- Add `pino` as dependency (not replacing console — dual-write)
- Add `pino-http` middleware for request logging
- Add request ID generation middleware (`req.id = uuid.v4()`)
- Keep `console.log` for backward compat but add `req.log` for structured traces

### 3.2 Health Check Improvement (`server.js`)
- Upgrade `/api/health` to report:
  - DB connectivity (actual query)
  - LLM key pool status (keys available / total)
  - PulseKit channel status
  - Uptime + memory usage
  - Version + last migration timestamp

### 3.3 Error Response Standardization
- Add `ApiError` class with code, message, status, details
- Standardize all route error responses to `{ error, code, details?, requestId? }`
- Add request ID to all error responses

### 3.4 Performance
- Add `compression` middleware (gzip/brotli for API responses + static assets)
- Add `Cache-Control` headers for static frontend assets
- Add `surrogate-control` for CDN support

## Risk Mitigation

| Risk | Mitigation |
|------|-----------|
| RLS re-enablement breaks queries | Keep DISABLE statements, add startup test, add feature flag to toggle |
| New middleware affects route behavior | Add after existing middleware, test with full suite before commit |
| Rate limiting blocks legitimate users | Set high defaults (60/30 req/min), document tunable env vars |
| Frontend a11y changes break layout | Add ARIA and role attributes only — no CSS/structural changes |
| ESLint adds noise | Use `eslint:recommended` with minimal custom rules |
